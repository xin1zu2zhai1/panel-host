# クイズパネル（ホスト）

クイズ番組の解答パネルのように、参加者がスマホで書いた答えを大きなパネルで一斉に表示するシステムのホスト画面です。
回答者用のページは別のリポジトリ **Answer** にあります。

- ホスト画面: `https://<ユーザー名>.github.io/panel-host/`
- 回答者画面: `https://<ユーザー名>.github.io/Answer/`

## できること

- **問題を複数登録**（記述・選択式・手書きフリップの3形式、配点と制限時間つき）。自動で保存され、JSON で書き出し・読み込みもできます。
- 参加コード（6桁）と QR コードを表示し、参加者はスマホで読み取るだけで参加できます。
- 出題 → 回答が届くとパネルのランプが点灯 → 締め切り → パネルを1枚ずつ、または一斉にオープン → 正解発表で ○ / × を表示。
- 記述問題は自動で判定します（全角・半角、ひらがな・カタカナ、大文字・小文字、空白の違いは同じとみなし、別解も登録可能）。パネルをクリックすると ○ と × を切り替えられます。
- 得点の集計、途中の順位表示、最終結果発表（回答者のスマホにも順位を表示）。
- 全画面表示（プロジェクター向け）、効果音、キーボード操作。

### キー操作（進行タブ）

| キー | 操作 |
| --- | --- |
| Space / Enter | 次へ（出題 → 締め切り → パネルを開く → 正解発表 → 次の問題） |
| A | 一斉オープン |
| J | 正解発表 |
| ← → | 問題の切り替え |
| R | 順位の表示 |
| F | 全画面表示 |

## 公開のしかた（GitHub Pages）

1. このリポジトリの **Settings → Pages** を開く
2. **Build and deployment** の Source を「Deploy from a branch」、Branch を `main` / `/(root)` にして Save
3. 数分後に `https://<ユーザー名>.github.io/panel-host/` で開けるようになります

回答者用リポジトリ（Answer）も同じ手順で公開してください。
ホスト画面は、同じユーザーの `Answer` を回答者ページとして自動で使います。
リポジトリ名を変えた場合は、`js/config.js` の `PLAYER_REPO`（または `PLAYER_URL`）を変えるか、ホスト画面の「設定」タブで回答者ページの URL を入力してください。

## 通信のしくみ

自前のサーバーは使いません。無料の公開 MQTT サーバー5つに WebSocket（wss）で**同時に**つなぎ、それを中継にしています。
ホストと回答者に共通でつながるサーバーが1つでもあれば動きます。

| サーバー | ポート |
| --- | --- |
| mqtt.eclipseprojects.io | 443 |
| public.cloud.shiftr.io | 443（ユーザー名・パスワード public） |
| broker.emqx.io | 8084 |
| broker.hivemq.com | 8884 |
| test.mosquitto.org | 8081 |

トピックは `{APP_NS}/{6桁の参加コード}/{種類}` です（`APP_NS` は `js/config.js`）。

| 種類 | 向き | 中身 | retain |
| --- | --- | --- | --- |
| `state` | ホスト → 回答者 | いまの状態を丸ごと（問題・受付状況・判定・得点など） | する |
| `player` | 回答者 → ホスト | `hello`（名乗り）／`ans`（回答）／`bye`（退出・遺言） | しない |
| `cmd` | ホスト → 回答者 | `rollcall`（名乗り直しの依頼）／`kick`（参加者から外す） | しない |

- QoS は基本 1、`rollcall` だけ 0。keepalive 30秒、再接続 4秒ごと、接続タイムアウト 10秒、clean: true、clientId は接続・再接続のたびにランダム。
- `state` は差分ではなく丸ごと送り、サーバーに保持（retain）させるので、途中参加や再読み込みでもすぐ最新の状態に戻ります。タイムスタンプが前回より古い `state` は無視します。
- 回答者は接続のたびに `hello` を送り、ホストも接続時に `rollcall` を送ります。回答者は遺言メッセージ（Will）で `bye` を預けておき、切れると 30〜45 秒ほどで切断として表示されます。オンライン状態はサーバーごとに管理し、全サーバーとの接続が切れたときだけ「切断」と表示します。
- 回答は「ホストに届きました」と確認できるまで自動で送り直します。判定はホスト側で計算します（回答者の申告は使いません）。
- ホストは10分ごとに `state` を送り直します。操作のない状態が6時間続くと新しい参加コードに切り替わり、古いコードの保持データは空にします（古いコードの回答者は参加画面に戻ります）。
- 新しいコードを決めるときは 1.5 秒待って使用中でないかを確かめ（最大5回）、この端末で最近使った 200 件も避けます。
- 状態はブラウザの localStorage に保存しています（使えない環境でも動きます）。同じホスト画面を2つのタブで開くと、どちらか一方だけが動くようにしています。

### 注意

- **公開サーバーを使うため、参加コードを知っている人なら誰でも通信を読めます。** 個人情報や秘密の内容は扱わないでください。
- ライブラリ（mqtt.js 5.10.1）は jsDelivr から読み込み、読み込めなかったときは `vendor/` の同じファイルを使います。

## つながらないとき

| 症状 | よくある原因と対策 |
| --- | --- |
| ずっと「接続を試しています」 | 会社・学校の Wi-Fi で特殊なポートが塞がれている → 443 番のサーバー（eclipseprojects・shiftr）だけでも動きます。スマホ回線に切り替えて試す |
| ホテル・カフェの Wi-Fi でつながらない | ブラウザでのログインが済んでいない → 普通の Web ページが開けるか確認 |
| 「ライブラリの読み込みに失敗しました」 | 広告ブロッカーなど → 止めるか別のブラウザで |
| スマホを戻したら表示が古い | スリープで通信が切れた → 画面に戻ると自動で再接続して最新の状態を取り直します |
| プライベートブラウズ | 再読み込みすると参加し直しになります |

## ファイル構成

```
index.html        ホスト画面
css/host.css
js/config.js      設定（接続先・APP_NS・回答者ページの URL など）※ 回答者側と同じ内容にする
js/net.js         複数サーバーへの同時接続（回答者側と共通）
js/common.js      共通の道具（判定・保存など。回答者側と共通）
js/host.js        ホスト画面の本体
vendor/           mqtt.js と QR コード生成ライブラリの予備
```

`js/config.js`・`js/net.js`・`js/common.js` は回答者側リポジトリと**同じ内容**にしてください。
